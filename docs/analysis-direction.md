# 分层归因与演示方向（2026-10-15 用户确认）

TraceLab 不依赖出现某个特定异常才开始工作。P0 的产品目标调整为先识别重要业绩变化，
再根据实际财务信号选择调查任务。重要性阈值尚待金融组确认，不新增异常分类或优先级规则。
当前程序输出逐项变化和方向性组合信号，不声称已实现重要性判定或 Agent 调查。

## 利润归因顺序

1. 营业利润：检查收入、成本费用、其他收益、投资收益、减值等实际组成项。当前仅选定总额核对，全量桥接仍待确认。
2. 利润总额：在营业利润基础上核对营业外收入与支出。
3. 净利润：在利润总额基础上核对所得税费用。
4. 少数股东损益：单独核对其变化和归属分配影响，不把它当作经营费用。
5. 归母净利润：由净利润减少数股东损益解释变化，再结合证据形成经营解释。

不得只围绕归母净利润直接寻找原因；不得把跨层级影响重复相加。
会计桥接说明金额如何衔接，经营原因仍须原文核验。

## 格力演示

继续采用格力2024—2025主案例。演示切入点为“利润下降，但经营现金流增长，两者走势分化”。
程序以合并净利润与合并经营现金流方向比较，归母净利润在利润分层结果中另列，避免混用归属口径。
不强行演示利润与收入增速明显背离；不适合某个预设信号不等于不适合作为演示公司。

演示目标为财务计算、动态调查、证据核验闭环。当前已实现前置计算、原文整理和确定性的调查问题准备，
动态 Agent 调查和因果证据判断尚未执行。

## 调查选择与边界

所有案例保留逐层利润调查，不以组合信号命中为运行条件。
当已计算的净利润差额小于零、经营现金流差额大于零时，增加利润与现金流调节调查。
数据缺失或阻断时不按零识别信号；没有命中该组合时不强加现金流分化结论。
收入、成本、费用等均依据实际变化和证据调查，不预先固定为毛利率原因。

现金流调查先核对现金流量表及补充资料，再检查营运资本、非现金及其他调节项。
这些是候选问题，尚不是已证实原因；现金流增长也不自动证明盈利质量改善。
需要补齐结构化调节项、两期出处及金融组确认的映射；保留合并范围变化的比较限制。

每次运行输出 investigation_plan.json，记录分层顺序、触发事实、调查问题与执行状态。
不改财务数值、既有勾稽规则、原始资料和历史运行结果，不调用模型。
