## 环境与实际测试

完整依赖入口 `requirements.txt` 引用既有 `requirements-stage2.txt`，唯一第三方运行/测试依赖为 `pypdf==6.10.0`；CSV 与模拟核查仅用标准库。README 声明 Python 3.10+，本轮完整验证使用 Python 3.12.14；没有声称逐一验证所有 Python 版本。

推荐从仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

若在本机受限沙箱遇到临时目录权限错误，在同一 PowerShell 会话执行以下环境修正，然后运行测试。它只改变本进程环境，不需要任何个人密钥。

```powershell
New-Item -ItemType Directory -Force tmp | Out-Null
$env:TEMP = (Resolve-Path tmp).Path
$env:TMP = $env:TEMP
python -X utf8 -m unittest discover -s tests -v
```

## 缺失资料与公开边界

新克隆缺少 `outputs/final_revision/20261017T093152-d80de1cefa` 整个快照；加载器要求其中 `release_hashes.json`、inventory、inputs、normalized、metrics、source_checks、financial_records、evidence、verification、verified_evidence、cash_metrics、cash_checks 等原有清单文件。不能仅复制一份 facts JSON 来声称来源重核成功。

从原始材料重建还需 `stage2.FILES/REVISED_FILES` 的六份资料（两份年报、对应Excel底稿、最新/早期Word及接口建议），最终版核验报告和底稿，以及对应 `(1)` 修订版 Word/Excel；需按阶段生成前序快照。第四阶段真实入口集成测试还依赖预检目录里的 preflight/export_scope。真实财务核查不依赖微信目录本身，完整快照的 inputs 副本足够；但这些私有副本没有随 Git 交付。

公开模拟例已提供，可展示完整确定性核查的软件行为。真实年报、内部附件和完整模型运行审计仍留在被忽略的本地 outputs；不自动打包。用户如需让评审重现格力来源核查，须决定有权提供哪些资料及交付方式，不能将内部材料直接公开。
