# AlphaTrace 前端业务主线与验收说明

2026-10-18。基于 main / 9b6a81d 及上一轮未提交的前端修改继续调整。没有 reset、commit 或 push。以本说明的三页主线为准，原两份离线集成文档保留作为历史数据接入记录。

## 产品与当前能力

定位：财务变化驱动的上市公司业绩归因与证据验证 Agent。用户浏览现有财务结果，沿财务信号查看历史 Agent 调查，再查看阶段性分析与证据。完整在线自主归因是产品目标，不是本轮已实现状态。

主导航只有：

1. 业绩分析：公司、期间、口径与主题；五项核心财务两期对比；净利润会计贡献；调查主题入口。
2. Agent 调查：已有目标、实际工具、返回来源、下一条实际记录、未完成原因。真实动作 search → get → error，3轮、2次工具调用、3次真实请求。
3. 核验报告与证据：财务事实、会计贡献、经营解释的明确空状态、公开年报证据目录与支持边界。

辅助入口：研究档案、指定 PDF 提取、结构化研报纠错、完整财务计算、证据原文。研报纠错仍是人为构造陈述的离线示例，不是首页或主要业务流程。

## 展示分层

默认呈现财务事实与业务边界。运行编号、validation_failed / incomplete_response、工具参数、允许公开的审计字段、资料修订历史和文件摘要放入折叠技术详情。原始数据没有删除或改写。

没有“等待人工确认最终AI解释”的用户交付卡片。当前格力未形成合规最终解释，报告直接显示“尚未形成经核验的最终经营解释”。财务来源核验结果仍可正常展示。61条来源记录不等于61条经营解释证据链。

净利润贡献按现成桥接行读取：项目自身变化与对净利润的影响分列，目标变化和残差原样展示，不跨利润层级相加。其他层级桥接、未闭合营业总收入和现金流勾稽保留在展开区。

## 操作与隔离

- 指标名称 → 对应财务详情 → 证据原文 → 返回来源页。
- 财务信号 → 真实历史 Agent → search/get 关联来源 → 原文和页码。
- Agent → 阶段性报告 → 会计贡献或证据目录 → 原文。
- 模拟 explain 节点仅定位已有模拟候选内容；不存在的关联显示未提供关联记录。
- 切换案例重置页面、证据与计算上下文。模拟案例保持醒目标记。
- 展示包缺失/校验失败时阻断真实分析内容，显示不可用提示；只有显式选择模拟案例后才展示模拟数据。
- 原始PDF不嵌入，只有既有公开摘录。不添加在线按钮、业务API、模型调用或审核写回。

## 截止日演示（约4分钟）

1. 业绩分析：展示公司、期间与利润下降/现金流增长主题，点击净利润查看金额和来源。

3. 从调查信号进入Agent：说明检索和读取确实发生，第三轮响应不完整，未形成合规解释；点击实际证据定位原文。
4. 打开阶段性报告：财务事实与原文可追溯，但经营归因尚未完成；没有虚构最终解释或待签核AI报告。

剩余边界：公司/期间仅能选择已有案例；尚无在线任意公司分析、完整真实Agent归因、在线上传、审核写回或报告文件导出。辅助详情的展开和滚动位置不跨页保持。不影响现有真实财务分析和历史轨迹演示。
