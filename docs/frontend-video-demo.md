# TraceLab（盈迹）初赛视频演示版

验收日期：2026-10-18。基于现有三页工作空间做展示层调整，没有新增后端能力。

## 页面与导航

首次进入独立产品介绍页：格力净利润与经营现金流同比对比、三个研究问题、产品方法、研究资料选择入口。它不占用主导航。

介绍页 → 选择研究资料弹窗 → 载入已核验案例 → 业绩分析 → Agent 调查 → 核验报告与证据。

品牌按钮随时返回介绍页。点击“选择研究资料”，选中格力 2024—2025 真实资料卡片后点击“载入已核验案例”。载入时通过既有适配器重新读取 gree-display.json（cache: no-store），核对案例、运行、资料版本和文件关联。校验失败留在弹窗显示错误，不沿用旧结果进入分析。未选中或真实包不可用时，载入按钮禁用。弹窗可通过关闭按钮、Esc 或“返回介绍页”关闭；关闭后迟到请求不会触发跳转。辅助财务详情及证据页保持返回来源页面的入口。

## 数据与展示边界

- 数据仍来自 `frontend/public/data/gree-display.json`，契约仍为 `alphatrace-display-v1`，适配器和 Python 导出器未修改。
- 展示包 SHA256 保持 `082f017e6b10789bb9eae133bf784d5f6433b4b7555aa6ea6d6ecdd1d4e919ca`。
- 开场比例直接读取真实记录的 `yoy`：净利润 `-10.84%`，经营现金流 `57.93%`；未在浏览器计算或编造走势。
- 主卡片继续展示精确元金额字符串。净利润变化 `-3508323271.19 元`，现金流变化 `17013864183.36 元`。
- 净利润桥接沿用后端：利润总额影响 `-2251336897.18`、所得税费用影响 `-1256986374.01`、变化残差 `0.00` 元；其他层级和现金流勾稽保留展开入口。
- Agent 默认业务视图显示实际 search/get。search 返回 E07_28、F_net_profit；get 返回 F_operating_cashflow。全部链接仅解析当前案例中已有来源。
- 完整三轮审计仍保留 `search → get → error`、`validation_failed / incomplete_response`、3 次请求 / 2 次工具调用。错误不是合理停止，更不是成功归因。
- “经营解释生成与证据校验”采用独立虚线区域，明确标记“规划能力 / 尚未完成”，不作为第三次已执行动作。
- 报告优先展示财务变化、会计贡献、61 条可追溯来源；这些来源不等于 61 条经营因果证据链。
- 指定 PDF 表格提取、结构化研报纠错仍是辅助离线结果；纠错陈述为人为构造示例。

## 5 分钟内演示路线

1. 0:00—0:35：打开 `http://localhost:8443/`，介绍 TraceLab 与利润、现金流方向分化的研究问题。
2. 0:35—1:35：点击“选择研究资料” → 选中格力案例 → “载入已核验案例”（约 10—15 秒）；随后展示五项金额与净利润会计贡献、影响和残差。
3. 1:35—2:45：点击“查看 Agent 调查过程”，展示真实 search/get，点击 F_operating_cashflow 查看原文及印刷 88 / PDF 89 页，再返回调查。
4. 2:45—3:15：说明虚线区域是待完善目标；需要时展开真实执行详情，展示完整三轮及失败状态。
5. 3:15—4:10：进入业绩分析与证据报告，展示财务摘要、桥接和 F_net_profit 原文（印刷 87 / PDF 88 页）。说明经营解释仍在完善。
6. 4:10—4:50：返回业绩分析，展开“资料与辅助核查工具”，简要展示 PDF 的十条 matched 结果及构造陈述的方向纠错。
